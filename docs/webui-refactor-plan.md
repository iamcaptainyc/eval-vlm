# WebUI 整体分析与免构建重构计划

日期：2026-09-21。分析对象：当前工作树，包含用户已有未提交改动。本文为计划，不代表已经实施。

协作角色按用户最新指定：Astra 负责规划、风险审查与最终验收，Terra/Luna 负责有界执行。

## 1. 结论与边界

项目已经具备完整的评测业务链和可用的 WebUI。主要问题是前端页面、状态、表单及渲染耦合，部分查询在数据增大后仍反复做全量工作，以及跨页面交互缺少统一的生命周期。建议保留 FastAPI、CLI 子进程和文件产物模型，采用原生 ES Modules、页面按需加载、组件化 DOM 和有界缓存逐步重构。

用户进一步明确的最高优先级是：**统一 UI 风格、修复交互缺陷，只保留深色和浅色两套主题，让实际数据优雅、舒适地自动排版。** 因此设计系统与真实数据结果页样板必须前置，不以单纯拆代码或后端微优化代替 UI 重构。两套主题共享完全相同的组件、布局与交互规则，仅替换语义颜色；不增加第三套风格或独立维护两份页面。

用户已明确选择：**保留免构建，优先模块化和性能优化**。部署端继续只需 Python 包，不引入 npm 构建、Node 服务、CDN 或新的前端框架。开发期的浏览器测试工具可作为独立可选依赖，不进入运行依赖。

优化分三个维度：用户完成审查与评测所需的操作数、浏览器加载/交互/内存开销、服务器查询/图片/日志开销。网页优化不能承诺提高模型推理吞吐；GPU 批处理和后端推理调优属于独立工作。

本轮完成源码审查、静态资源统计、测试覆盖检查及 `node --check`。设计示意另通过 headless Edge 的 12 组交互/布局检查（两主题 × 两数据集 × 320/768/1024 px），无脚本错误、页面级横向溢出或表格列数不一致，并检查深浅截图。示意没有接入真实 API；没有执行原应用浏览器回归、API 性能基准或 GPU 实验，所有时延、内存和吞吐预算均为待验证目标。当前可用 Python 运行时缺少 pytest、FastAPI、httpx 等项目依赖，未运行 pytest，也未为分析安装依赖。

## 2. 项目整体结构与应保留的基础

```text
配置层 config.py / workspace.py / templates
                     ↓
CLI cli.py → split / pred / eval / field-eval / sweep / compare / report
                     ↓
data → runner / predict → inference backends → results/store → scoring / reports
                     ↑
WebUI: FastAPI 查询/编辑 API + JobManager 启动 CLI 子进程
                     ↑
浏览器: index.html + app.js + styles.css
```

| 层 | 当前责任 | 重构取舍 |
| --- | --- | --- |
| 配置与工作区 | YAML 配置、数据集定位、模型扫描、产物路径 | 保留格式与命令兼容；统一配置批量写入与版本校验 |
| 数据层 | LlamaFactory 记录、多轮目标、图片路径、切分 | 保留解析语义；查询索引与原始文件分离 |
| 推理层 | OpenAI/vLLM、MNN、HF、离线 vLLM、llama.cpp、fake | 保留后端协议及线程安全/批处理策略 |
| 结果层 | JSONL 预测、评分、指标和报告；断点续跑 | 保留文件为事实来源；增加可重建的查询缓存/索引 |
| Web 服务 | 浏览、样本编辑、配置更新、报告、任务 API | 拆路由与服务；隔离同步重工作 |
| Web 前端 | 导航、全局状态、全部页面与可视化 | 重构重点：页面边界、统一组件、上下文一致性 |

值得保留的实现：样本删除/恢复、单图与 `<image>` 占位符同步、审计与备份、SHA 冲突保护、run stale 标记、图片路径校验、结果分页接口、离线报告、任务取消/续跑与 SSE。这些是迁移时的回归基线。

注意：样本 ID 包含位置与内容哈希（`data/loader.py:35`），删除记录会改变后续 ID。此次重构继续沿用旧结果失效机制，不顺带更改 ID 或迁移历史结果。任务调度当前已有 eval/convert 两条 lane（`webui/jobs.py:132`），不能按旧文档当成单队列重写。

## 3. 当前前端规模与真实技术栈

以 Python `splitlines()` 统计物理行；压缩大小为本地 gzip 默认设置的估算，不是浏览器网络测量。

| 文件 | 行数 | 原始字节 | 本地 gzip 字节 | 当前责任 |
| --- | ---: | ---: | ---: | --- |
| `static/app.js` | 6,981 | 308,656 | 66,473 | 189 个顶层函数声明、全局状态、全部请求/渲染/事件 |
| `static/index.html` | 2,534 | 168,653 | 34,085 | 11 个页面、表单、弹窗、全局导航 |
| `static/styles.css` | 7,429 | 169,154 | 26,003 | 基础主题、布局、页面样式及覆盖规则 |

三份文件原始合计约 631 KiB，gzip 估算约 124 KiB。这里的关键不只是传输量：页面首次加载时仍需解析所有模板、CSS 和页面代码。

HTML 有 386 处 `style=`、270 处常见内联事件属性；JS 有 113 行包含 `innerHTML`。这些是职责集中和样式维护成本的信号，不应直接等同于 113 个性能问题。需要按实际重绘频率和渲染规模治理。

当前是**原生 JavaScript，无 CDN 依赖**。README 中 Alpine.js 的表述，以及 `docs/webui-plan.md` 中“当前没有可视化层”等文字已经过时；后者应标注为历史初建方案。本计划针对现在的实现。

## 5. 已确认的问题与优先级

以下“确认”指代码路径存在，不代表已经测得用户端故障频率。

| 优先级 | 证据 | 影响 | 改造 |
| --- | --- | --- | --- |
| P0 | `app.js:182` 切页改 hash 后加载；hashchange 又经 `handleHash` 加载；`295` 数据集切换也有双入口 | 一次导航可能发起重复请求/重绘 | 路由成为唯一页面加载入口，导航动作只更新路由 |
| P0 | `loadSamples:462`、`loadConfig:1464`、`loadRuns:2946` 等完成请求后直接更新共享状态 | 快速切数据集时旧响应可能覆盖新上下文 | 请求取消 + context generation 校验 + 按数据集查询键隔离 |
| P0 | `saveAllConfigChanges:1733` 从 DOM/class 收集配置；`configio.py:29` 逐键调用 `set_dataset_value` | 配置草稿与目标上下文耦合；多次磁盘写；失败可能部分生效 | 固定草稿归属，按差异提交，批量校验后单次原子提交 |
| P0 | `styles.css:2990` 起浅色大量具体选择器覆盖，HTML 有 386 处行内样式 | 两主题外观不一致，修一页容易破坏另一页；属于用户明确的主要痛点 | 两套语义 token + 一套组件样式，结果页先做完整样板 |
| P1 | `app.js:2795` 日志拼接整段字符串并重设 `pre.textContent` | 日志越长，每条更新成本越高；内存无明显界限 | 环形缓冲、分批追加、历史分段加载 |
| P1 | `jobs.py:606` 历史日志 `f.read()`，每个订阅者无界 Queue | 大日志回放和慢客户端增加内存/循环开销 | 分块回放、游标、带上限的订阅队列、落盘补读 |
| P1 | `runsio.py:258` 全量解析 scored.jsonl 后过滤/排序/切片；`361` 全量读取 field mismatches | API 返回分页但计算开销仍随全文件增长 | 文件版本缓存、行/筛选索引，页面只富化所需记录 |
| P1 | `locks.py:76` 同步文件锁获取位于 async 路径；编辑接口直接执行同步文件处理 | 锁等待/大量 IO 可能阻塞事件循环 | 将完整持锁事务放到受控线程，或采用非阻塞异步锁获取 |
| P1 | `app.py:88` 仅 app.js/styles.css 的带 v URL 设 immutable；版本是 HTML 手工字符串 | 拆模块后缓存规则不完整；漏升级版本可能使用旧代码 | 全模块发布版本目录或内容指纹；HTML 重验证 |
| P2 | CSS 与 HTML 大量内联颜色和叠加覆盖 | 明暗主题、响应式和新组件容易产生回归 | 语义 token、分层 CSS、页面作用域 |
| P2 | 部分前端测试检查源码字符串（`test_webui_jobs.py:96` 等） | 函数重命名会破坏测试，但不能证明交互正确 | 增加浏览器行为测试并逐步淘汰脆弱文本断言 |

额外确认的正确性缺口：`datasets.py:76` 的列表缓存签名漏掉 `results/store.py:148` 中的 `predictions.jsonl` marker，可能漏更新只有预测产物的新 Run；`app.py:304` 配置写入与任务没有共同资源准入；`jobs.py:80` 元数据直接写入，需原子替换。多数分页参数和图片尺寸也缺少统一范围校验。这些应建立单独回归用例。

现有优化不是零：`datasets.py:24` 已有 raw records/缩略图/数据集列表有界缓存；`app.py:81` 已启用 gzip；任务已做 single-flight 轮询与日志 session 保护；Sweep 结果已有 requestId/超时/取消。应提取这些有效模式形成统一基础设施。

## 6. 整体 UI 重构

### 6.1 信息架构

将拥挤的横向全功能导航改成固定全局外壳 + 上下文导航。业务入口分为工作区、数据集工作台、实验、任务、设置。

```text
顶栏：工作区 / 当前数据集 / 当前页面          任务摘要  主题
┌──────────────┬──────────────────────────────────────────────┐
│ 工作区       │ 页面标题、数据版本与主操作                    │
│ 数据集       │ 筛选条 / 搜索 / 视图切换                      │
│ 实验         ├──────────────────────────┬───────────────────┤
│ 任务         │ 主列表、画廊或结果表格    │ 选中样本/Run详情  │
│              │                          │ 按需打开          │
│ 当前数据集   │                          │                   │
│ · 样本       │                          │                   │
│ · 结果       ├──────────────────────────┴───────────────────┤
│ · 模型对比   │ 分页 / 选择计数 / 操作反馈                    │
│ · 配置       └──────────────────────────────────────────────┘
│ · 质量与回收 │ 全局日志抽屉（按需打开，可调整高度）
│ 设置         │
└──────────────┘
```

“质量与回收”下保留健康检查与回收站两个子页。Sweep 启动和结果归为“实验”的两个子页。全局数据集选择器只影响数据集工作台，不隐式改写实验多选数据集或已打开任务的归属。

路由示例：`#/datasets`、`#/datasets/{name}/samples?filter=missing&page=2`、`#/datasets/{name}/runs/{runId}`、`#/experiments/new`、`#/experiments/results`、`#/jobs/{jobId}`、`#/settings/models`。保留旧 hash 的重定向适配。

### 6.2 页面交互设计

| 页面 | 新布局和操作流程 | 用户效率收益 |
| --- | --- | --- |
| 数据集总览 | 紧凑表格：名称、样本数、run 数、过期状态、最近任务；点击进入并恢复上次子页 | 数据集多时减少大卡片滚动和重复选上下文；首版不增加无必要的卡片模式 |
| 样本 | 工具栏固定；网格/列表切换；卡片只显示缩略图、ID、简短摘要和问题标签；右侧详情显示完整多轮对话与原图 | 浏览列表时避免渲染全部长对话；审查不中断筛选位置 |
| 样本详情 | 支持上一条/下一条、键盘导航、复制 ID/路径、图片切换；单图删除与整条删除分开说明 | 连续审查少开关弹窗，删除范围明确 |
| 配置 | 左侧分类导航、右侧当前分类表单；基础字段展开，高级字段折叠；固定保存栏显示已改项、校验错误与目标数据集 | 降低长页认知负担，降低保存到错误上下文的风险 |
| 结果 | 左 Run 列表，中间指标和筛选表，右样本详情；顶端显示 eval/field-eval 口径与数据版本 | 从聚合指标直达问题样本；保留双模式语义 |
| 模型对比 | 固定 baseline，候选列横向滚动；图片、真值、上下文只展示一份；回归/改进/缺失/错误直接筛选 | 减少重复图片与对话，优先检查有意义的差异 |
| 实验启动 | 顺序为“数据集 → 评测方式与模型 → 参数 → 提交摘要”；复用 JobForm | 避免三个启动入口各自维护参数语义 |
| 实验结果 | 先展示紧凑汇总和异常；选中数据集后再加载字段矩阵/详细图表；大矩阵独立滚动 | 避免首屏堆满所有数据集的图表 |
| 任务 | eval/convert lane 清晰分组；显示排队、运行、结束原因；启动器为侧栏；选中任务打开日志 | 减少“启动表单 + 全部历史 + 大日志”的同屏竞争 |
| 健康与回收 | 问题列表跳转样本；恢复时明确影响 run 数与版本变化；完成后就地反馈 | 修复闭环可追踪，不让用户反复找目标 |
| 设置 | 工作区/图片路径/模型目录/模型转换分类；扫描显式刷新且展示时间 | 不在每次切页反复扫描模型目录 |

批量选择可先支持筛选、对比或导出；批量删除属于新增写能力，必须另外实现一次持锁、一次备份、一次版本校验的后端事务后再开放，不能在浏览器循环发送 N 次删除。

### 6.3 视觉与可访问性

- 采用 4/8 px 间距阶梯；常规控件高度 32–36 px，工具栏 44–48 px；桌面侧栏约 208 px、详情栏约 360–480 px，最终由内容与可用宽度验证。
- 将颜色收敛为 surface/text/border/accent/success/warning/danger 等语义变量；明暗主题仅替换变量。保留可识别的主色，减少满屏渐变、辉光和大阴影。
- 数据表强调对齐、密度和可比较性；数值使用等宽数字，单位和评分口径固定位置显示。颜色外同时提供图标/文字，不能只靠红绿传达正确性。
- loading、empty、filtered-empty、error、stale、saving、conflict 使用统一状态组件；重试在失败区域就地呈现，toast 不替代持久错误说明。
- >=1280 px 使用完整侧栏和可选详情；768–1279 px 收起侧栏/详情抽屉；更窄视口支持查看、筛选、取消任务等关键流程，复杂对比表允许横向滚动。
- 所有控件有 label、可见焦点；dialog 管理焦点进入/返回和 Escape；列表保留键盘可达性；日志不逐行触发屏幕阅读器播报；遵循减少动画偏好。

### 6.4 严格限定为两套主题

以下为设计起始值，最终必须对真实表格、长文本、图表、禁用/错误/选中状态逐一验收。

| 语义 token | 浅色 | 深色 | 使用规则 |
| --- | --- | --- | --- |
| canvas | `#F5F6F8` | `#111418` | 页面背景，不叠加装饰渐变 |
| surface | `#FFFFFF` | `#191E25` | 内容表面与表单 |
| surface-subtle | `#F0F2F5` | `#222933` | 表头、次级区域、hover |
| text-primary | `#1E293B` | `#E5EAF1` | 正文和指标值 |
| text-secondary | `#526174` | `#A7B3C4` | 分母、描述和次要字段 |
| border | `#DDE2E8` | `#343E4B` | 稀疏分隔线，不给每块内容套框 |
| accent | `#255FD1` | `#89B4FF` | 当前选中、链接与定量主系列 |

统一字体层级：标题 20–24 px、区块标题 16 px、正文/表格 14 px、辅助信息 12 px；正文行高约 1.6。正文不使用超低对比灰色，不为挤下更多列而缩到 10–11 px。圆角限于 6/10 px 两档，阴影只用于浮层；普通表格和内容分区主要依赖留白与分隔线。

主题开关只有“浅色 / 深色”，首次可从系统偏好选择其一，之后记住用户选择。按钮、输入框、表格、弹窗、滚动区、日志和图表统一响应；不允许页面自己覆盖为固定白底或黑底。主按钮使用专用的 accent-surface/on-accent 配对，不能直接套正文 accent 色。结果好坏使用 success/warning/error 语义色并配文字，不把每个字段随机染成不同颜色。

实施时完整 token 合同还需包含 surface-elevated/selected、text-disabled、border-strong、focus-ring、accent-surface/on-accent、success/warning/danger 的 surface/border/text、backdrop、code/log，以及图表 sequential/diverging/neutral 色阶。页面业务 CSS 不写颜色字面量；主题选择器仅用于根节点 token 重定义，SVG/canvas 从计算后的变量取色。

组件变体收敛：Button 仅 primary/secondary/quiet/danger，Badge 仅 neutral/status，Surface 仅 plain/raised/selected。对每个适用组件验收 default、hover、active、focus、disabled、loading、error、selected × light/dark；页面不能私自再定义一套“特殊按钮”。

正文对比目标至少 4.5:1，大字号文本至少 3:1；实际组合需测量，不能只按 hex 目测。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 6.5 自动排版是可预测规则，不是任意挤压

| 内容 | 自动布局规则 | 必须避免 |
| --- | --- | --- |
| 指标概览 | 容器足够宽时 3–4 列，缩窄自动变 2/1 列；每项标签→值→口径/分母 | 卡片越多越小、长标签压住大数字 |
| 字段指标 | 4 个字段优先紧凑表格；更多字段分页/搜索；同一数值列对齐 | 每个字段一张不同风格大卡片 |
| 表格 | 数字列固定合理宽度，名称列弹性；表头/标识列按需 sticky；仅表格区域横滚 | 页面整体横滚、强迫所有长路径换成十几行 |
| 长模型名 | 展示“日期时间 + 模型家族 + 后端”语义片段；完整原始名称可展开/复制，消歧必需信息常显 | 只截开头导致各模型看起来一样；自动改磁盘目录名 |
| 对话/描述 | 列表摘要 3–4 行，可展开；详情自然增高，宽屏两列对照、窄屏上下对照 | 固定高度裁掉答案；多列挤成单字竖排 |
| 样本图 | 图片框比例统一且 object-fit:contain；保留原图查看；多图自动换行 | 为美观裁掉道路标志/面部等评测内容 |
| 多模型对比 | baseline 固定；候选每列保留可读最小宽度；超出局部横滚或分组选候选 | 将 5–6 个模型硬塞进屏幕而无法阅读 |
| 混淆矩阵 | 根据 label 数和最长标签算最小列宽；小矩阵完整展示，较大矩阵局部滚动；视口内不缩小数字 | 缩成不可辨认的小热力图；去掉稀有类但不说明 |
| 筛选工具栏 | 自然换行，高频项优先，低频项收进“更多条件” | 用绝对定位固定按钮，文字一长就重叠 |
| 空/异常 | 缺失指标显示“未提供/不可用”，0 显示真实 0；空预测、抽取失败、未评测独立状态 | `value || 0` 把缺失、失败都变成 0 分 |

容器布局可用 `grid-template-columns: repeat(auto-fit, minmax(min(100%, 220px), 1fr))`，配合 `min-width:0` 和局部 overflow；表格按语义列规则单独布局。优先 CSS Grid/Flex 和容器断点，不让 JavaScript 每次 resize 手算全部位置；DOM 阅读顺序保持稳定，不用 dense packing 改变业务顺序。[MDN 自动排版说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Auto-placement)

验收契约：主网格使用 `minmax(0,1fr)`；DataTable 外壳 `max-inline-size:100%`，只有表格局部 overflow；数字用 tabular-nums；样本级候选列保留约 320–360 px 最小阅读宽度，超过可容纳数量时局部横滚；正文 `white-space:pre-wrap` 并允许长路径 `overflow-wrap:anywhere`。以容器宽度而非只有 viewport 决定详情与表格布局，200% 缩放下操作仍可达。

## 7. 前端目标架构

```text
static/
  index.html                  # 仅应用外壳和入口
  app.js                      # 迁移期兼容入口，最终仅启动应用
  core/
    router.js                 # hash 解析、旧路由适配、导航守卫
    context.js                # workspace/dataset/route + generation
    api.js                    # 错误、超时、取消、响应解码
    query-cache.js            # key、single-flight、有界缓存、失效
    events.js                 # 少量有类型约定的业务通知
  components/
    data-table.js  pagination.js  filter-bar.js
    image-viewer.js  sample-inspector.js
    dialog.js  toast.js  status-panel.js
    model-selector.js  command-preview.js  log-viewer.js
  features/
    datasets/  samples/  config/  runs/  comparison/
    experiments/  jobs/  settings/  quality/
      page.js                 # mount/update/unmount
      service.js              # 该领域 API
      model.js                # 本页状态/纯计算/验证
      template.js             # 静态模板或组件构造
      styles.css
  styles/
    tokens.css  base.css  layout.css  components.css
```

目录为职责建议，不要求每个简单页面创建四个空文件。组件仅在确有复用或独立生命周期时拆分，避免为“组件化”另写一套通用框架。

页面接口统一为 `mount(root, context)` 返回 `update(nextContext)` 与 `unmount()`。路由负责动态导入、挂载和销毁；页面退出取消页面请求、移除监听器、停止本页定时器并关闭其 overlay。任务摘要和全局日志由外壳持有独立生命周期，避免切页意外中断任务可见性。

入口显式使用 `<script type="module">`，所有 import 使用相对 URL，避免浏览器无法解析的 bare specifier。页面 CSS 由共享 `loadStylesheet(new URL('./styles.css', import.meta.url))` 去重加载，可保留已加载的作用域样式；动态 import 不会自动加载 CSS。大表单采用同目录 `view.html` 按需读取，小组件使用 DOM/template，避免只是把旧巨型 HTML 转成巨型 JS 字符串。页面只关闭自己拥有的浮层，不能误关 shell 的日志、任务活动和 toast。

原生 `import()` 可按需加载页面模块，无需引入构建工具；基础组件静态导入，昂贵的页面/图表动态导入，避免拆出过多串行小请求。[MDN import()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import)

### 状态分层与请求一致性

1. **路由状态**：数据集、run、筛选、分页等可分享内容在 hash 路由参数中。
2. **服务器状态**：API 结果按 `[workspace,dataset,resource,parameters,revision]` 缓存，有容量/过期策略；不与配置草稿共用对象。
3. **页面状态**：展开项、选中行、滚动位置只归本页；必要时按路由键短暂保留。
4. **编辑草稿**：绑定数据集和基础配置 revision，保存成功后替换基础快照；保留不同数据集的草稿边界。
5. **全局界面状态**：主题、导航折叠和任务摘要；不把全部业务数据再次塞回一个大 store。

发请求时捕获不可变 context token；离页或换数据集时 `AbortController.abort()`，响应提交前仍校验 token。取消用于节省无用客户端工作，token 用于防止已经返回的旧结果提交；取消不能保证服务器停止运算。[MDN AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)

配置离页提供保存/放弃/取消；切换前不先覆盖当前数据集。后台响应与表单初始化不能清除用户已经产生的新草稿。任务表单复用后端字段定义，但配置默认值与单次任务覆盖必须显示清楚：当前 CLI 会持久化部分覆盖，第一阶段保持语义并明确提示；若以后需要“一次性覆盖”再独立修改核心协议。

### DOM 与样式迁移

- 由 `onclick="globalFunction(...)"` 转为组件绑定或根容器事件委托，业务文本使用 textContent/DOM 属性。移除动态数据嵌入可执行事件字符串的做法。
- 保留成熟的纯格式化/图表计算函数；仅更新变化节点，不每次刷新整页。
- 先依赖现有分页：24 张样本图、20/30 行明细不必全部引入虚拟列表。长任务历史、长日志、大矩阵达到基准阈值时再窗口化。
- 使用 CSS `@layer` 明确 tokens/base/components/pages 的顺序，减少 `!important` 主题补丁；页面样式加作用域类。
- 紧凑页面骨架/固定图片宽高减轻布局跳动；原图只在需要时加载，缩略图延续 lazy loading。

## 8. 后端效率与数据一致性设计

### 8.1 拆分边界

`app.py` 只保留应用工厂、生命周期、中间件和路由装配。按 datasets、samples、config、runs/comparison、jobs、experiments、settings/tools 拆 `APIRouter`。现有 datasets/runsio/editing 等代码先作为服务保持行为，之后再抽 repository/cache；`models.py` 明确作为请求/响应模型，避免和本地模型扫描混淆。

Settings、JobManager、缓存逐步归属 `app.state`，通过依赖注入访问，避免模块单例跨 workspace/测试应用串扰。第一阶段继续采用单 Web 服务进程与现有两条任务 lane；不能通过直接增加 Uvicorn worker 数来扩吞吐，否则任务队列和内存锁将分裂。

FastAPI 普通 `def` 路由通常在线程池执行，当前多数读接口已经如此。问题主要是 `async def` 内直接调用的同步函数，不需要把所有路由再包一层线程。[FastAPI async 文档](https://fastapi.tiangolo.com/async/)

### 8.2 查询与缓存

| 资源 | 第一阶段 | 数据规模扩大后的选择 |
| --- | --- | --- |
| 数据集列表 | 保留现有缓存，合并重复刷新；显式失效与短期目录签名复核结合 | 后台刷新目录索引，避免每次请求遍历所有 run 标记 |
| 样本 | 保留 raw records + SHA 缓存；复用解析/搜索文本；先筛选后仅解析当前页 | 可重建 sidecar 索引；不改变 test.json 原格式 |
| scored.jsonl | 按文件版本复用解析与筛选数据；只为当前页补图片/对话 | 行偏移或 SQLite 派生索引，按分数/轮次/ID 查询 |
| field mismatches | 复用 JSON 解析结果、筛选索引 | 生成派生检索表，大结果不反复整体加载 |
| 多 run 对比 | 缓存已对齐结果/摘要，分页只切片和富化 | 以 run 版本组为键重建，限制缓存总字节及并发构建数 |
| 模型目录 | 明确刷新、短 TTL、单次扫描共享结果 | 目录规模较大时后台扫描，UI 显示上次成功时间 |
| 健康检查 | 复用版本相同的报告，提供显式重新检查 | 将长扫描作为受控后台任务返回进度 |

缓存键应包含绝对路径、mtime_ns、size，以及会影响解释的配置/图片根目录版本；仅 test.json 的时间戳不足以区分 mapping/eval.targets 等变化。写入、恢复、配置修改、任务完成触发显式失效；外部 CLI 修改通过文件签名复核发现。

缓存必须有**总字节预算**和淘汰策略，不能仅限制“4 个数据集”而忽略单个数据集大小。缓存构建 single-flight，避免同时请求相同大文件时重复解析；读文件前后核对版本，变化则重试/不发布混合版本。

针对这次真实数据，两个 test.json 合计约 0.97 MiB，常用产物也仅数 MiB。先做 stat-key 缓存、查询参数上限、汇总一次遍历及正确失效；当文件超过例如 20 MiB / 50,000 行且基准未达标，再评估 sidecar/SQLite。这是候选触发线，不是预先承诺采用的架构。

任意关键字过滤在没有对应索引时仍可能需要全量工作，应明确成本。只有 benchmark 证明必要才引入 SQLite 派生索引；它是可删除重建的缓存，不成为业务数据库，不要求迁移原始文件。

### 8.3 图片链路

保留现有缩略图缓存和允许目录范围验证（当前并非逐条校验图片属于样本集合，旧设计文档对此描述不准确）。缩略尺寸按场景限定档位（例如 256/512/768），避免任意尺寸生成无限缓存；键包含源文件版本、尺寸、编码格式和质量。

使用稳定的 ETag、条件请求和图片版本 URL；源图变化后不能让旧 URL 的长期缓存掩盖新内容。缩略图生成采用受限线程/并发和 single-flight。内存缓存按字节限制，只有重启后重复解码成本显著才增加磁盘缓存。图片根目录修改必须同时使解析缓存失效。

### 8.4 日志与任务

- 日志文件保持完整事实来源；默认只回放最近一段并提供“加载更早”和下载，不默认将数百 MB 历史塞进页面。
- 协议使用单调 event sequence 或文件字节游标，定义 UTF-8 边界、截断/轮转和恢复语义；不要用 JavaScript 字符串长度作为 Python 文件 seek 偏移。
- 回放分块，先订阅后回放的现有保护保留；以游标去重衔接历史与直播，状态终态不可遗漏。
- 订阅队列有上限；慢客户端落后时发出重新同步提示并按游标从磁盘补读，不能静默丢掉关键终态，也不能阻塞执行器。
- 前端例如每 50–100 ms 或每帧批量刷新，保留最近约 5,000–10,000 行的可见缓冲，真实阈值由基准确定；暂停滚动不等于停止收日志。
- 保留当前 single-flight、terminalSession 和重连退避，抽入 LogViewer/JobService。任务摘要按可见性/活跃任务动态调整轮询；无必要时停轮询。
- 保留 eval/convert lane 行为。后续需对 GPU/CPU/内存资源冲突建立准入策略，而不是无条件增加并行数；转换是否使用 GPU 必须依据实际执行方式判断。

### 8.5 写入事务

配置更新：读取一次 → 核对 revision → 在内存应用全部 diff → 全量校验 → 同目录临时文件写出并原子替换 → 更新缓存 → 审计。失败时旧文件完整保留，保留 YAML 注释与未知字段。不能逐键写成功一半再报错。

当前任务子进程不获取 WebUI 的配置文件锁。短期对排队/运行任务所依赖配置采用明确忙状态保护；长期可将配置快照/hash 固定到任务与 run，但这需要同时改 CLI 的配置载入和持久化覆盖行为，不能只在 metadata 存一份快照就声称任务已经隔离。任务 meta.json 也应原子替换；异常重启需识别可能存活的子进程，不能仅更改显示状态。

样本删除/恢复继续保留 SHA、备份、split_meta 和 stale 语义。优化同步 IO 时，将文件锁获取/持有/释放安排在一致的线程或异步锁实现中；尤其不能只把 acquire 放到另一线程，却在事件循环线程 release，破坏锁实现的线程语义。任务开始和编辑操作需要共享数据集资源准入，避免“检查未忙 → 等锁 → 任务启动”的时序窗口。

## 9. 静态资源部署和缓存

继续由 Python wheel 携带 `static/**/*`。模块拆分后先默认重验证，避免新模块误用旧内容；稳定后使用发布版本目录（如 `/assets/<release>/...`）或内容指纹。所有相对 import 留在同一版本目录，不能只给入口加 `?v=` 就认为整个模块依赖树已版本化。

HTML 始终重验证；不可变版本资源使用长缓存；更新 wheel 后 HTML 指向新版本。发布时保留一段旧版本资源或提供升级刷新提示，覆盖长时间打开页面后再懒加载的情况。不需要 npm/前端构建；可由 Python wheel 发布步骤生成版本目录/清单，内容指纹必须有明确生成步骤和 wheel 内容测试。

## 10. 实施顺序、产物与验收门槛

以下为一名熟悉项目的开发者的粗略人日估计，包含功能验证，不是交付日期承诺。P0/P1 以基准结果确定优先级。

| 阶段 | 预计 | 范围与具体交付 | 验收门槛 |
| --- | --- | --- | --- |
| 0：数据与设计基线 | 2–3 人日 | 真实数据画像、两主题 tokens、统一组件状态表、自动排版规范、可运行免构建结果样板与状态页；同时记录请求与性能基线 | 只读 fixture 驱动，三档宽度截图/交互验收；深浅主题同结构；长名称/空值/两类指标不溢出、不误读 |
| 1：上下文正确性 | 2–3 | 单一导航入口、context token、统一 API 错误/取消、配置草稿归属、路由兼容 | 快速切 A/B 不串数据；单次导航不重复请求；草稿不静默丢失 |
| 2：统一外壳和首批页面 | 3–5 | 免构建 core/生命周期/按需加载；统一表格、指标、表单、弹窗；落地真实数据结果页与样本页 | 已迁移页面同时通过两主题/三档宽度；无各页独立主题补丁 |
| 3：全站 UI 迁移 | 4–6 | 数据集总览、比较 inspector、配置页、JobForm、实验、任务、设置和质量页面 | 全站共享组件；审查→定位→修改/重跑→对比的端到端流程通过 |
| 4：规模与流畅度 | 3–5 | 按基准优化 scored/comparison、图片档位、日志游标/分块/有界渲染、事件循环隔离 | 大数据翻页不重复解码全量文件；长日志内存有界；断线不漏终态 |
| 5：事务与发布收尾 | 2–4 | 配置原子批量更新、资源准入、app.state 生命周期、缓存版本发布、文档与测试整理 | 注释/未知字段不丢；409/取消/恢复正确；wheel 离线安装后全部模块可达 |

总量约 16–26 人日，复杂矩阵或大规模索引可单独延期。事务正确性若基线复现出实际数据风险，应从阶段 5 前移至阶段 1；拆 router 可以随对应服务变更逐块完成，无需等一次整体重写。实际工作目录只有数百样本/每集数个 run，不能为了假设的十万样本规模推迟当前最需要的 UI 统一。

迁移顺序以真实垂直功能为单位：结果样板与样本 → 数据集/对比 → 配置 → 任务/实验 → 设置/质量。每迁移一页删除其旧逻辑，迁移期通过旧路由适配和有限兼容入口共存，不能长期同时维护两套前端实现。

实施时按用户最新指定：由 Astra 完成计划/风险审查与集成验收，worker/Terra 执行模块与回归工作，quick_worker/Luna 执行小型低风险修改。可并行但互不重叠的范围为前端 core、后端查询缓存、任务日志、测试夹具；具体接口先确定，禁止多个 worker 同时改旧 app.js 或 app.py。并行 worker 不超过四个。

## 11. 验证方案与性能目标

### 代表性负载

- 小：1,000 样本、2–5 个 run，用于交互与兼容。
- 真实体验基线：用户提供的两个数据集及全部 run，用于确认两主题、长模型名、道路字段口径、情绪两轮、旧版指标、图片路径缺失等真实展示问题；数据只读，写测试使用副本。
- 中：10,000 样本、10 个 run、常见多轮对话/多图，用于分页与对比。
- 大：100,000 样本、50 个 run、长日志，按真实文件大小另记录；不能假设样本数量等价于字节数。
- 日志：10/100 MB 历史、稳定新增以及短时高频输出；测试慢客户端、断线和中文 UTF-8 边界。
- 所有写测试使用临时 workspace 和 fake 后端，不在用户真实数据上做删除/恢复验证。

### 首轮目标（基线建立后调整）

| 指标 | 建议目标 | 测量方法 |
| --- | --- | --- |
| 导航请求 | 同一 query key 同时最多 1 个在途请求 | 浏览器网络记录与服务请求计数 |
| 上下文一致性 | 20 次快速切换和随机延迟下 0 次旧结果提交 | 浏览器自动化控制响应顺序 |
| 本地基础交互 | 选择、展开、切页反馈 p95 <100 ms；按需加载时间另计 | Performance trace，固定设备/浏览器 |
| 中等数据热分页 | API p95 <200 ms 的初始目标；冷构建单列 | 固定 SSD/机器/并发度，至少重复 30 次 |
| 首屏 | 应用壳+当前页的 JS/CSS/HTML 压缩总量先争取较基线下降 >=30% | 同等功能入口、网络传输统计；不计图片 |
| 日志 | 缓冲达到上限后不再随全日志大小增长；页面持续可交互 | 30 分钟压力 trace、JS heap 和 DOM 计数 |
| 服务内存 | 稳态缓存容量受可配置字节预算约束 | RSS、缓存命中/淘汰/字节统计 |
| 重复查询 | unchanged 数据翻页不再完整重新解析 scored/comparison 输入 | 文件读取/解析计数器 |

不能保证每个过滤条件都 O(page_size)：无索引文本搜索、首次构建和外部文件变更仍有全量成本，UI 应显示可取消的加载状态。

### 测试矩阵

保留现有 7 个 `test_webui*.py` 文件及 comparison/核心测试所覆盖的 API、锁、样本编辑、字段评测、Sweep、设置模型与队列行为。新增重点是测试实际行为，而非复制实现函数名。

1. 路由：刷新/前进后退/旧链接、数据集切换、同页筛选持久化、非法路由回退。
2. 竞态：A 慢 B 快、相同请求去重、取消后迟到响应、提交后切页、不相干页面状态隔离。
3. 配置：未保存离开、同名数据集不同 workspace、版本冲突、非法值零落盘、批量中间失败、注释保留。
4. 样本：整条/单图删除、恢复、图片占位符与 split_meta 同步、run stale、409、忙状态与锁等待竞态。
5. 缓存：CLI 外部写入、配置 mapping/图片根变化、新 run、mtime_ns/size 更新、超预算淘汰、并发首次构建。
6. 日志：订阅期间退出、历史/直播衔接、重连去重、慢客户端、UTF-8 游标、取消后进程真正退出、两 lane 互不误取消。
7. 结果：eval/field-eval 口径、mixed SHA 拒绝、回归/改进/缺失分类、分页总数、原图和上下文正确对应。
8. 视觉：明暗主题、三档宽度、键盘访问、焦点恢复、长中文/路径/多模型列、空/错/过期状态；两主题 DOM 结构一致，无页面级横向溢出，200% 缩放可用；0/缺失/失败不同义，颜色不是唯一编码；组件状态页建立截图差异基线。
9. 发布：wheel 包含所有模块和样式、HTTP MIME 正确、离线运行、静态版本升级与旧页面懒加载。

## 12. 首批实施任务建议

优先批准阶段 0–2，加上日志的有界渲染；这是收益明确且方便逐步回归的第一批。

- 先确定仅两主题的 tokens、组件状态和自动排版规则，用道路/情绪结果页验证，再推广到全站。
- 单一 router 入口 + context token + 请求去重，先解决重复加载和跨数据集状态覆盖风险。
- 提取 API/页面生命周期/基础外壳，迁移结果样板与样本页，验证免构建方案实际可维护性。
- 日志按批次渲染并限制浏览器缓冲；完整历史仍在文件中，保持用户获取完整日志的能力。
- 基准确认后再选择 scored/comparison 索引的具体实现，避免在小数据上过度引入存储层。

后续实施应在上述方案获批准或用户明确要求继续后进行。本次仅新增分析计划文档，不修改应用代码及用户已有改动。
